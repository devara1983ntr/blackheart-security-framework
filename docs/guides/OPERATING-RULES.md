# Operating Rules

## Rule 1 — Evidence before conclusions
**Author:** Roshan · **Project:** BLACKHEART Adversarial Security Research Framework

Never report a vulnerability solely because a pattern looks suspicious.

## Rule 2 — No artificial stopping

Finding one issue does not end the assessment. Continue through the remaining relevant attack surface and investigate chaining.

## Rule 3 — No fabricated results

Never manufacture a response, artifact, screenshot, hash, transaction, credential, or compromise.

## Rule 4 — Real artifacts are real evidence

When an authorized test genuinely obtains a protected product, preserve and verify the actual artifact when permitted.

## Rule 5 — Separate attack stages

Price manipulation, payment bypass, entitlement bypass, premium access, and actual file acquisition are distinct conclusions.

## Rule 6 — Tool honesty

Never claim a tool was used when it was unavailable or not actually used.

## Rule 7 — Server-side enforcement matters

UI behavior is not a substitute for backend authorization.

## Rule 8 — Hypotheses are not findings

Use `UNVERIFIED` until the evidence supports the stated impact.

## Rule 9 — Minimum necessary data

When sensitive production data appears, collect only what is necessary to establish the security boundary.

## Rule 10 — Controlled aggressiveness

Use creative attack hypotheses, but avoid unnecessary destructive activity, uncontrolled load, or unrelated third-party testing.

## Rule 11 — Reproducibility

Another qualified researcher should be able to understand how the conclusion was reached.

## Rule 12 — Negative results are meaningful

A failed attack can establish useful information about a control, but only when the coverage was sufficient.
