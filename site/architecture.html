Architecture

Five layers.
One of them always wins.

A security agent is exactly as trustworthy as the skills you load. The whole design exists to make that statement structurally true rather than aspirational.

Precedence

The ladder is total.

When two layers disagree there is no arbitration step, no vote, and no tie to break. The order is fixed and the higher entry simply wins.

  1. ConformanceBlackhearts-authored rules. Non-negotiable, and they are what everything else is measured against.
  2. SafetyStanding constraints on the agent itself. Cannot be relaxed by content.
  3. Task scopeWhat this specific run was authorized to do. Narrow by default.
  4. Adapter contractWhat this skill declares it will do, and what it declares it will never do.
  5. Vendored contentUpstream instruction. Advisory. Never authoritative about its own safety.

The rule that makes the rest work

Vendored content is last, and it is last on purpose. A skill's own SKILL.md gets no vote on whether it is trustworthy, because a document that could raise its own permissions would make the adapter layer decorative.

The gate

A refusal is the control working.

Most security tooling is judged by what it lets through. This one is judged by whether it stops. The gate is declarative — flags, not executable policy — and weakening it fails the build.

Declared, not inferred

The gate is a JSON5 document of flags that CI parses. It contains no executable policy at all. If a rule could be phrased as code, a rule could be phrased as a backdoor, and nothing would notice.

Zero credentials, by construction

Not "zero credentials used in the exercise" — zero credentials are requested or handled, for the target, for payment, or for the agent. Write capability is answered by static analysis and reasoning, never by writing to find out.

Design

Why these choices and not the obvious ones.

Mirror everything, not just skills

A mirror that contains only skills is not a mirror. Commands, personas, plugin manifests, scripts and audit history are all vendored, because the parts of a supply chain that go unexamined are the parts that matter.

Personas are hostile input

The 33 vendored agent personas change how an agent reasons and what it agrees to. They are mirrored and documented, and they are disabled by default — treated as untrusted instruction rather than as configuration.

Record defects, do not patch them

111 dead links inside vendored files are registered individually with reasons instead of fixed. Editing them would break byte-identical mirroring, and a mirror that quietly diverges is worse than one with recorded blemishes.
