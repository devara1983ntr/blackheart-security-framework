A governed security-supply-chain framework for AI agents

Skills are not the problem. Unvetted skills are.

The problem

A security agent is only as trustworthy as the skills it loads. Install an unvetted skill and you have handed an autonomous system a third-party instruction — one that can read files, run shell commands, and exfiltrate. There is no lockfile, no signature, no audit trail, and no way to tell a helpful prompt from a hostile one.

The industry currently answers this with a README. That is not a control.

What BLACKHEART does

Untrusted by construction

All 3,864 vendored files are third-party text, mirrored byte-for-byte and never modified. They are input, not policy.

Reviewed per unit

Every skill and collection sits behind a _BLACKHEART-ADAPTER.md declaring what it does and what it must never do.

Conformance wins

Where vendored content and the conformance layer conflict, conformance wins. A persona cannot widen scope, disable a gate, or authorize a target.

A gate that fails the build

requireAuthorizedTarget, requireAdapter, denyTargetsWithoutScope. Switching one off is a CI failure, not a suggestion.

Upstream drift is visible

Daily comparison against the pinned commit. Detection is automated; merging is not.

Defects are recorded, not hidden

111 dead links in vendored content are individually registered with a reason. Vendored bytes are never patched.

The evidence rules

  • A finding is a hypothesis, never a conclusion. It becomes a finding only after independent demonstration.
  • A clean result is a coverage gap, not a clearance. An untested category is reported as untested.
  • Negative results and rejected hypotheses are preserved. They are evidence.
  • Severity is bounded by evidence status. An unverified item is excluded from the severity scale entirely.

The most security-relevant vendored tool — a jailbreak detector — still had three real defects after passing a full static audit. A framework that only runs scanners would have shipped those silently.

Responsible use

BLACKHEART is for authorized security work. It is not for attacking systems you do not own or have written permission to test. No target is engaged without a recorded authorization; no credential is ever requested or handled; no production data is modified; findings default to UNVERIFIED.
